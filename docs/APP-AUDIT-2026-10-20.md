# ECOD app audit — 20 October 2026

## Result and scope

Reviewed the assessment application across administrator, candidate and assessor workflows. Testing used disposable local JSON stores, mocked Airtable/Blobs backends, and the isolated Netlify PR 50 preview. Production records were not modified.

This is evidence of the tested workflows and failure cases, not a guarantee that every possible browser, device, network condition or future change is bug-free.

## Confirmed issues fixed

| Issue | Effect | Fix and verification |
| --- | --- | --- |
| Automatic booking always wrote `assessor_id: null` | New booked tests had nobody assigned to review them | Added an optional active default assessor per track, administered in Roles & Frameworks → track → Edit. Bookings, individual onboarding and CSV allocations use the track fallback; explicit/candidate choices take precedence. Separate RSA/SAMA defaults, assessor queue isolation, inactive/deleted accounts, input validation, retry/repair and existing reassignment preservation are tested. A real Netlify SAMA booking inherited its default and appeared in that assessor's queue. |
| Pagination accepted fractional and infinite boundaries | Directory metadata could disagree with actual array slices; non-finite offsets serialized incorrectly | Normalize page sizes and offsets to bounded integers. Regression checks cover candidates, users, questions and assessments, including fractional, infinite, negative and malformed offsets. |
| Airtable fallback deletion swallowed operational errors | A cleanup could report success while permission/service failures left records behind | Missing rows still count as already absent. Actual deletion failures now propagate so the caller can report failure and retry. Tests reproduce the old false-success behavior and verify the repaired behavior alongside deletion recovery and cascade tests. |

The new track column retains a readable minimum width for track names and scrolls inside its table card. Existing tests are not reassigned when a track default changes; use Assessments → Reassign for previously unassigned tests.

## Browser and point-of-view checks

- **54 administrator layout cases:** Dashboard, Candidates, Assessments, Test bookings, Roles & Frameworks, Question Bank, Users & Access, Audit Log and Settings at **320, 768 and 1280 CSS pixels**, in both themes. Reduced-motion accessibility mode was also exercised. No page-wide horizontal overflow, route error panels or intersecting visible controls were found in the measured states. Wide tables scroll inside their cards.
- **15 candidate/assessor layout cases:** candidate journey, assessor queue, scoring/playback, assessor report and candidate report at the same three widths. No measured page overflow or intersecting visible controls.
- **Candidate browser journey:** sign in, read instructions, acknowledge exam rules, answer and lock two MCQs, submit, and return to the journey with the assessment under review.
- **Assessor browser journey:** open assigned submitted work, read the saved transcript, play a synthetic one-second WAV answer, save a 4/5 open score, finalize, and obtain the expected **90%** report (5/5 objective + 4/5 open).
- **Post-finalization evidence:** the score input is disabled and the stored audio remains playable (`readyState: 4`, one-second duration, no decoder error).
- **Candidate report privacy:** the candidate sees the same 90% result, without assessor identity, internal feedback or internal question-level detail.
- **Live Netlify check:** save a SAMA track default, create a single-use invitation, book a synthetic candidate and verify the assessment's assignment and the assessor's queue against real preview storage. The dashboard shows the new upcoming slot.

Closed accordion descendants were excluded from overlap measurements: they can retain layout rectangles while the browser correctly hides their content. Initial geometry flags in the Question Bank were investigated and were not visible UI overlaps.

Local screenshots and machine-readable measurements are stored under `.probe/full-app-audit-20261020/`. Preview verification is under `.probe/default-track-assessors/`. These local artifacts and synthetic credentials are deliberately excluded from Git.

## Code quality observations

The shared API entry point keeps local and Netlify behavior aligned. Fixed candidate/assessor projections, snapshot-based papers, bounded request timeouts, serialized score saves and conditional storage updates are useful safeguards and are covered by tests.

The administrator handler and view files are large. Splitting them by workflow would improve maintenance, but a broad rewrite during this stability audit would add risk without correcting an observed defect. Keep future changes small and retain the regression suites. Airtable still lacks the cross-instance conditional-write primitives used by Blobs; its tests do not establish the same concurrency guarantees as the current Blobs deployment.

The changes are prepared for review in PR 50 and its isolated deployment preview. This audit does not merge or replace the production deployment.
